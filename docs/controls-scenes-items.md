# 操控、场景与物件（3.2）

### S03 · 输入、移动与控制权

**明确需求：** 保留跟随镜头方向的 WASD，调快基础移动速度，默认按住 Shift 加速跑。提供键鼠和手柄绑定设置，支持改绑、保存、恢复默认；室内外共用，转场时不响应移动。

**当前默认绑定：** 左键攻击、右键按住防御、Ctrl 松手翻滚、R 拔出／收起已装备的主手武器、F 使用／对话。靠近可对话 NPC 时先尝试对话；成功后本次不会拾取。

**桌面摆放：** 小屋餐桌的面包可按 F 拿取；背包有面包时，靠近原面包板按 K 放回一份。满板、错误物品、菜单、转场与超距不会转移；K 如已改绑，优先执行绑定动作。

**槽位数据：** `world_slots.gd` 校验「槽位 ID、用途、放入者 ID」。餐桌沿用 `cabin.dining.bread.01` 的来源余量和角色背包，板上最多一份；重新摆满即恢复场景初值。居民床沿用 `resident_routes.gd` 的 `BEDS` 名册，每床只接受对应居民，不接受物品。占用从居民已存日程读取：本人停在自己的床位且活动为睡眠才算占床，离床即释放；不另外保存占用表。

**调试镜头：** 普通模式不旋转。室外开发模式的 Ctrl + 左拖不触发攻击或翻滚；Ctrl 单独按下时先等待，松开且未组成左键手势才翻滚。

**实现建议：** 用 InputMap 的 `sprint` 动作，步速与跑速分别可调；手柄先用左摇杆移动并保留模拟力度，跑步键实机试过再定。第一版不必接体力。

**首轮已实现：** 保留镜头相对轴向，步速从 1.82 调至 **2.45**、跑速 **4.1**（均为可调临时值，`Walker` 的 `walk_speed` / `sprint_speed`）。左杆用 `Input.get_vector` 保留有效区间内的幅度（测试死区 0.2），斜走不额外加速；无体力消耗。两位角色由根节点统一上锁，关菜单、读档或过门后须先释放仍按住的移动/跑步。战斗动作和伤害见 [S11 原型](./combat-prototype.md)。普通玩家可滚轮缩放；室外开发镜头须显式启用 `--dev-camera` 或根节点属性。

当前由旅途手册（F2／Esc／默认 Start／右下角「设置」）进入「操控与改绑」，按键鼠/手柄两列改绑，另一类设备不变。成功立即写 `user://input_bindings.cfg`，可恢复项目默认；冲突或坏配置有提示。WASD/方向键、Shift、Tab 行囊、F2 设置不变；**手柄玩法动作键是可改测试默认**：左杆移动、LB 奔跑、X 攻击、A 使用／对话、RT 防御、RB 翻滚、L3 拔／收刀、Back/Select 行囊、Start 设置。菜单内十字键移焦点、A 确认、B 返回，确认控件时不同时使用世界物件。F5/F6/F9 是验收保留键，Esc 为取消。旧光照快捷键让位于绑定的玩法动作。

### S04 · 镜头、渲染与场景切换

**明确需求：** 室外区域之间能连续步行，不黑场、不传送、不重新接管角色。室外与房间之间保留 Demo 的门槛和黑场切换；进出门不改变玩家身份、背包和日期。

**视角与渲染范围：** 目标是斜俯视的 2D 式画面体验；当前 Demo 用 3D 实现，不因此预设远眺需求或更换渲染管线。画面只覆盖玩家附近，远景模型 LOD 不是当前重点。室外无缝仍需考虑邻块预加载、碰撞就绪和跨边界卡顿；具体加载范围和视觉优化按实测定。场景卸载只移除表现，不决定地区是否继续运行，见 S08。


**首轮已实现：** 小屋仍用原先的有向门槛、双视口和收拢/展开黑场。室外湖岸与坡上的边界只是现有石路上的一个标记；走过时仍是同一角色、同一地面和碰撞、不锁输入。只挂载当前区的轻量 `RegionReadout.tscn`（托盘、非空样品与读数），离开释放，不要求卸载共享地景。不是整张地图流式加载，未据此承诺加载半径、帧时或远景 LOD。

室内模块、家具摆放和持久状态的要求见 [模块化室内与家具](./interiors.md)。

### S05 · 目标选择与通用交互

提示、候选排序、执行校验；供拾取、容器、休息、对话复用。

**优先级需求：** 多个可拾取物品重叠时，用物品定义上的稀有度权重排序，越稀有越优先。**实现建议：** 先筛选在交互范围内且当前可用的目标，再对重叠物品按稀有度降序；同权重按距离、稳定 ID 排序，避免提示抖动。稀有度不让远处物品抢焦点；物品和门、NPC 等不同类型之间的优先级另议。

### S06 · 物品、背包和容器

定义与实例、堆叠和转移；供消耗、交易、掉落复用。 **阶段与讨论：** 地基：先只做单一占位物和容器转移；重量与装备现已接入原型，耐久延后。

**首轮已实现（S05 / S06）：** 近身使用的测试半径为 **1.55 m（临时）**。只考虑当前地点、有效且未取空的来源；对同时可取的地面堆按定义稀有度降序、距离升序、实例 ID 字典序选一个。执行时再校验距离/库存，一次转移整堆。空地面堆隐去，空箱保持开盖并提示。不同类型若同时成为候选则不擅自选一个；门仍靠走过门槛，未设物品、门和 NPC 的通用优先级。两堆同类样品验证稳定来源；不同稀有度只在隔离用例中临时复制定义，不多做可玩物品。

**装备原型（S06 / S12）：** F5 默认在行囊发放一把长剑、一把长枪，旧档缺少测试武器时补发；稳定来源记录与当前归属共同防止重复发放。主武器和主手是同一槽；此外有头部、副手、衣服、裤子、鞋、戒指、吊坠和手环。首批只有剑、枪可进主手，其余栏为空且无属性效果。装备和卸下在行囊与槽位间移动单件；换装归还原件，背包与装备的总负重不变。室外 v2、建筑局部坐标 v3 增加可选的 `equipment` 字段；旧档缺字段视为空。出鞘状态不存档。Q／R3 不再切换武器。

### S09 · UI、提示、音效与设置

HUD、交互反馈、日结结果可读性，基础音量/显示设置。 **阶段与讨论：** 地基先做提示与成功/拒绝反馈；正式界面、辅助功能按需求扩。

#### 统一角色面板（装备／行囊／属性）

**三区同屏：** 两条细墨线把同一张磨损羊皮纸分成装备、行囊、属性三栏，纸缘缺口透出暗化后的实际场景。左栏在独立透明 3D 视口里渲染当前主角的全身模型（默认 Isaac，切换主角也随之切换），周围有九个槽；空槽是低对比图标，装备后显示物品图标。中栏图标、物品名和右对齐数量各占固定位置，选中整行暖棕；列表滚动时下方的说明和装备／卸下按钮位置不变。重量是实际总携带重量，无负重上限。右栏从角色状态读取生命（暗红条）、力量／韧性和到下一点的成长进度（细金条），未启用属性与法力只留文字；没有角色等级、独立属性菜单或互斥页签。

**操作：** 默认 Tab／Back 聚焦行囊，F7／Y 或血条旁的「属性」按钮聚焦属性；都打开同一角色面板。方向键／十字键移焦，Enter／A 或鼠标可装备选中的剑枪；选装备槽确认即可卸下。Esc／B、Tab 或「关闭」回到世界。面板锁定移动、战斗、使用及存读档快捷键，不改 SceneTree 全局暂停。对话保持独立输入与界面。

**尺寸与纸材：** 角色面板使用 [全局 UI 逻辑框与安全区](ui-layout.md)，不经过 `Pixels`／`RoomPixels`。544×246 排版在 16:9 占 **85.0% 宽 × 68.3% 高**，三栏约 **35 / 33 / 32**；控件字体从共享语义档取得。保留暖奶油底、细纤维、斑驳旧边、透明撕缺及小角饰的程序纸材，控件仍继承共享主题。纸娃娃绘制范围独立于透明视口的纹理分辨率，全身留在九槽之间。列表／说明溢出时滚动，不挤占底部操作区。

- **实窗证据：** [本轮两档同机位截图及字号、净空与裁切量测](ui-layout.md#ci010-实窗数据)。2560×1440 全屏标题／物品行／说明为 **68 / 56 / 56 px**，960×540 窗口为 **25.5 / 21 / 21 px**；与世界档位无关。`previews/character-panel/` 是更早一版的历史图。
- **显示方式：** 独立进程默认普通全屏（不是独占全屏），F2 →「退出全屏」回窗口，亦可重新切入。默认内部世界仍为 480×270，`-- --320` 仍为 320×180，继续最近邻等比、不裁切。编辑器嵌入预览由编辑器容器管理，游戏内全屏按钮禁用；在编辑器关闭嵌入运行，或用 `--windowed --resolution 960x540` 从独立窗口启动。

### 体验迭代 · 当前界面与物件规则（S01 / S02 / S05 / S06 / S09）

本节更新首轮只用湖畔石的例子。新加互动以仓库根 [AGENTS.md](AGENTS.md) 的通则为准：靠近用于预览、使用才取物；规则先确认归属，成功后从场景原物飞向角色，不把动画状态写入存档。

- **物件与状态：** `item.sample`、`item.bread`、`item.cup` 各有名称、说明、图标。室内原餐桌的一条面包和一只茶杯分别是 `cabin.dining.bread.01`、`cabin.dining.cup.01`：切纹随面包、杯沿和茶面随杯子飞走，砧板留在桌上。空来源、堆叠和地区库存继续使用同一份 v1 状态；旧档未记录的新来源使用地图初值。箱盖随距离围绕铰链开闭，空箱保持开盖。飞物约 0.3 秒，仅表现，可被读档／切换打断。
- **同一套界面材质：** 暖羊皮纸、深墨字、旧皮革和黄铜色控件；角色面板保留暗幕和选中说明，列表每行左侧是物品定义的图标。拾取清单贴着物件投影，列出范围内物品及数量，用 ◆ 标记首项。视口缩放或相机移动时跟随，在边缘翻向或限位；不拦截鼠标，菜单和黑场期间不显示。地区标牌、时间牌和反馈也沿用这套纸面材质。
- **纸边验收：** 项目的 `gui/theme/custom` 指向 `res://scripts/ui/parchment_theme.tres`。大纸页的面、厚度和贴地阴影沿同一条不规则剪影绘制；短纸签、皮革按键另用适合小尺寸的端部。`tests/paper_edge_checks.gd` 在实际 Godot 窗口渲染背包和设置，逐边与「只保留暗幕」的颜色及 alpha 对照：960×540 和 320×180 均通过，四边不靠圆角也有透景起伏，正文与按钮没有跨入缺口。新增页面用同一标准验收。
- **设置与存读档：** 右下角按钮、Esc 或已绑定的设置动作（默认 F2 / Start）打开旅途手册。原单槽和快捷键不变；书内第一次保存直接写入，覆盖／读档要再次确认。无档时不能读；坏档错误在手册中显示，保留当前局面。改绑是设置子页，返回后仍在手册中，游戏输入不穿透。
- **独立验收：** `tests/table_checks.gd` 验证两件真实桌物、靠近开盖但不发货、飞行和取消；`tests/inventory_ui_checks.gd` 验证定义图标、选择和三种尺寸的浮签。真实渲染下 `tests/play_checks.gd -- --case=table-menu` 从出生点步行进屋、由门口走到桌侧，实点手册存读；飞行中保存，取走下一件再读回，库存、原物与浮签同步恢复。

**湖岸通行回归（S04）：** 温室临水侧至岸灯之间，原局部地面过陡，角色胶囊被坡面挡住而不是正常登上石路。仅修整这段干岸的可走坡度，并同步土面、铺石和植被，未放宽角色全局跨步／坡角。`source/bake_terrace.gd` 与 `art/terrace/BanksideRise.tscn` 同步。`tests/shore_checks.gd` 用实际 Traveler 在 6 个起点上坡、反向返回、沿岸双向走，并跑向水边、温室外墙与岸灯，均通过；0 帧进入水面多边形。51 个干岸采样中地面碰撞与可见网格最大差约 2.82 cm。陡处已有站姿仍可能一脚悬空，未将通行修复当成足部 IK 重做。

**室内地板回归（S04）：** 在低分辨率斜视下，深色地基透过极窄板缝、板面细木纹的几何覆盖都可能呈现断续暗点。只关闭地板自身投影没有改善，因而保留家具／灯光阴影。木板面下 2 mm 增加木色衬底，细木纹略加宽、减小对比；仅 `RoomPixels` 的 3D 几何使用 4× MSAA，室外视口、480×270 默认像素尺寸及最近邻放大不变。`tests/floor_checks.gd` 在相同机位对比原状、局部修复无 AA、2×、4×：四个固定取样区的高反差孤立暗点分别为 **39 / 28 / 15 / 5**，其中地毯侧边从 **3 到 0**。这是局部实测，并非所有角度或所有纹理暗像素都消失；低端 GPU 的帧时未测。

**池塘泥岸（S04）：** 裸露岸带应可读为草地 → 较干泥土 → 窄湿泥 → 浅水，不给水面加一圈匀宽描边。借鉴 [Mushreb · DEV LOG.03](https://www.bilibili.com/video/BV1KyjN6iEzq) 以深度／阈值分层、把水面高光独立处理的思路；本场景用 `source/bake_terrace.gd` 从现有水面同轮廓烘焙局部双通道距离图，由 `meadow.gdshader` 在原土面上着色，不另叠几何、不依赖屏幕深度或手绘瓦片。普通草、蕨和花按同一泥岸范围留出叶梢余量，池中芦苇与岸石保留。烘焙会随池岸轮廓重算，仍用原水位、浅水和断续高光、倒影及碰撞；不做动态水位、流体或扩图。

**实测：** Windows / Godot 4.7.2 / GL Compatibility，`tests/pond_render_checks.gd` 真窗口验证 3 个方位与缩放（480×270、320×180），分别取 14:00、18:40、01:00。九组的干泥／湿泥／水边均有可量测色差，固定机位的泥岸样本未见跨帧跳变；66 个岸线测点的泥岸宽约 **0.40–1.18 m**，198 个岸边／入水土面采样与水面至少相隔 **5.19 cm**，1,432 个岸区草木顶点无侵入。每个时段都在两个机位量到真实镜面贴图贡献；反向近镜未量到超过阈值的贡献。复跑 `tests/shore_checks.gd`：通行回归 0 失败、0 帧进水。连续手动环绕的观感和其他显卡未验。

**复跑：** `godot --path . --script res://tests/pond_render_checks.gd`（不开 `--headless`；加 `-- --capture` 可在 Windows 临时目录生成九宫格截图）；`godot --headless --path . --script res://tests/shore_checks.gd`。日常验收可在池边用滚轮和开发镜头 `--dev-camera` 的 Ctrl＋左拖对比岸带，走回石路并沿岸测试水边阻挡。
